# Sidecast — design decisions

Outcome of the design interview (2026-10-26). "Sidecast" is a working name.

Sidecast turns an Android phone into an **extended display** for a Mac over **Wi-Fi**.
It is a new, smaller codebase that ports the proven core of
[SideScreen](https://github.com/tranvuongquocdat/SideScreen) (MIT, see `THIRD_PARTY_NOTICES.md`).

| # | Decision |
|---|----------|
| Q1 | Two deliverables: a macOS app shipped as a `.dmg`, and an Android app shipped as an `.apk`. |
| Q2 | Personal use first: ad-hoc signed DMG, sideloaded APK. Structured so Developer ID signing + notarization can be added later without rework. |
| Q3 | True **extended** virtual display (private `CGVirtualDisplay` API). No mirroring in v1. |
| Q5 | Touch on the phone controls the Mac with SideScreen's full gesture set (tap, double tap, long-press = right click, long-press-drag = drag, 1/2-finger scroll with momentum, pinch = zoom). Held buttons are always released on disconnect (SideScreen bug #71). |
| Q6 | Mac: Apple Silicon, **macOS 15+** (bumped from 14 because in-memory TLS identities need `kSecImportToMemoryOnly`). Android: **Android 10+ (minSdk 29)**, targetSdk 36. Codec is negotiated: HEVC when the phone can decode it at the needed size, else H.264. |
| Q7 | Latency first: 60 fps default, adaptive bitrate, a max-bitrate/quality setting for text-heavy use. |
| Q8 | Toolchain via Homebrew (JDK 21, Gradle, Android command-line tools, platform-tools). |
| Q9 | New codebase; port virtual display, capture, encoder, decoder and gesture logic from SideScreen; rewrite app shell, settings and protocol. Drop website, demo mode, QR scanner (ML Kit), Play in-app updates. |
| Q10 | Accept the private `CGVirtualDisplay` API, isolated in one module. No Mac App Store. |
| Q13 | Menu-bar-only Mac app (`LSUIElement`), small SwiftUI settings window. |
| Q14 | Name **Sidecast**; bundle id / applicationId `com.achreftlili.sidecast`. |
| Q15 | **Wi-Fi only** in v1. No adb dependency on the Mac. (USB via `adb reverse` is a v2 candidate.) |
| Q16 | Discovery via **Bonjour** (`_sidecast._tcp`), one-time pairing with a **6-digit code shown on the Mac**. Manual IP entry as fallback. Works on a phone hotspot too. |
| Q17 | **TLS** on every connection; the phone pins the Mac's self-signed certificate at pairing; every connection must authenticate with a device token (no unauthenticated access, unlike SideScreen's loopback hole). |
| Q18 | TCP + **app-level frame acks**: cap frames in flight, drop frames *before* encoding when the link backs up, AIMD adaptive bitrate. Heartbeats so a dead link shows "Connection lost" instead of a frozen frame (SideScreen #72). |
| Q19 | System sleep (`pmset -a disablesleep 1`) is disabled **only while a phone is connected**; restored on disconnect. Menu bar shows when sleep is disabled. |
| Q20 | Root for `pmset` via a **sudoers rule** installed once (one admin prompt) that allows exactly `/usr/bin/pmset -a disablesleep 0` and `… 1`. The rule is validated with `visudo -c` before install. A menu item removes it. |
| Q21 | Crash safety: a detached watcher process restores sleep if the app dies for any reason; the app also restores sleep on every launch if a marker says it had disabled it. |
| Q22 | **Keyboard from the phone** (v0.2): a keyboard button on the phone opens the Android keyboard; typed text goes to the focused Mac app as Unicode (layout-independent), special keys as KEY events. Voice typing from the phone keyboard's mic works too. |
| Q23 | **Phone mic as a Mac microphone** (v0.2): our own HAL audio driver adds a **"Sidecast Microphone"** input device (installed once with an admin prompt). |
| Q24 | The phone records **only while a Mac app is using Sidecast Microphone** (MIC_CONTROL from the Mac), with a phone setting to disable the feature. |
| Q25 | While a phone is connected, Sidecast Microphone becomes the Mac's **default input** (previous default restored on disconnect); toggle in Settings. Audio is 48 kHz mono 16-bit PCM from Android's voice-communication source. |
| Q27 | **Trackpad-style gestures** (v0.3): 2-finger tap = right-click; 3/4-finger swipe left/right = switch Desktops / full-screen apps, up = Mission Control, down = App Exposé (injected as the Mission Control keyboard shortcuts). 3-finger tap stays the phone's stats toggle. |
| Q28 | **Remote access over the internet via Tailscale** (v0.4): no router changes, nothing exposed publicly; Sidecast TLS/pairing on top. The Mac advertises its LAN + Tailscale addresses in SERVER_HELLO; the phone tries LAN first and falls back to Tailscale automatically. |
| Q29 | **Data saver on mobile data** (default on): the phone asks for ≤ 4 Mbps and 30 fps when its network is metered. |
| Q30 | Remote use needs the Mac awake: Settings shows a hint to enable "Prevent automatic sleeping on power adapter when the display is off". No new always-on sleep blocking. |
| Q31 | **Trackpad mode** (v0.5): a toggle on the phone switches between touchscreen (absolute) and trackpad (relative cursor, tap = click at cursor) for precise apps like VS Code. |
| Q32 | **Human-like clicks + visible trackpad pointer** (v0.6): clicks are injected as move → down → ~40 ms → up (Electron apps like VS Code drop instant clicks); in trackpad mode the Mac streams its pointer position (CURSOR) and the phone draws a large pointer overlay. |
| Q26 | Mac builds are signed with a local self-signed **"Sidecast Local Signing"** certificate so macOS keeps permissions across updates. |
| Q33 | **Open source, built from source** (0.6, 2026-10-30): Apache 2.0. Users clone the repository and install with `make install-mac` / `make install-android`; no app stores, notarization or paid certificates. Each Mac creates its own "Sidecast Local Signing" certificate with `make mac-signing`; the phone app is installed over adb (exempt from Android developer verification). Mac builds target the host architecture (Intel compiles, untested). |
| Q34 | **Hosts announce their OS** (2026-10-31, protocol 1, additive): SERVER_HELLO carries `platform` (`macos` / `windows` / `linux`) and the Bonjour TXT record `os`, so Windows and Linux hosts work with the existing phone app without a version bump. Absent means `macos` (older Mac hosts); an unknown value shows as a generic computer. The phone stores the platform with each pairing (older pairings load as `macos`), says "computer" instead of "Mac" in its UI, shows the OS in the list of computers, and gives the macOS Screen Recording steps only to Mac hosts. The platform is for display and advice only: the protocol is the same for every OS. Kotlin names (`PairedMac`, `MacList`…) are kept to avoid churn. |
| Q35 | **iPhone / iPad client** (P4 preview, 2026-10-31): a UIKit app in `ios/`, iOS / iPadOS 17+ (iPads stuck on iPadOS 17 make good second screens), landscape, full screen, screen kept awake. Its protocol and client logic (connect planner with LAN → Tailscale fallback, session state machine and reconnect loop, touch sequencing, keyboard diffing, microphone state machine, data saver) is in `SidecastKit/Client`, unit-tested with the Mac tests and shared with `sidecast-probe` where it fits (TLS client setup, Annex-B → VideoToolbox). Network.framework TLS with the certificate pinned per candidate address; pairings and the device id in the Keychain (this device only, kept across the 7-day reinstalls of a free Apple ID). VideoToolbox decodes into an `AVSampleBufferDisplayLayer` with every picture shown at once. UIKit touches are re-sequenced into Android `MotionEvent` semantics (one DOWN/POINTER_DOWN per finger, lowest free pointer id), so hosts see the same TOUCH from both clients; Apple Pencil is a finger. The keyboard is a hidden text field whose edits become TEXT/KEY by diffing, so autocorrection, input methods and dictation work. Microphone through AVAudioEngine with voice processing, foreground only. Built from source: XcodeGen `project.yml` plus the generated, committed `Sidecast.xcodeproj`; `make install-ios` reads the user's team and bundle identifier from a gitignored `ios/Local.xcconfig`, builds with `xcodebuild -allowProvisioningUpdates` and installs with `devicectl`. A free Apple ID works but expires after 7 days; a paid account lasts a year. |
| Q36 | **A shared Rust core for the Windows and Linux hosts** (2026-10-31): a Cargo workspace in `rust/`. `sidecast-core` ports `SidecastKit` (protocol, pairing, flow control, stream planning, gestures, keyboard, jitter buffer, addresses) with its tests and the §8 vectors; the gesture engine emits platform-neutral actions, 3/4-finger swipes as semantic actions (`DesktopNext`, `DesktopPrevious`, `Overview`, `AppWindows`) that each host maps to its own shortcuts. `sidecast-server` is the host (tokio, rustls with the `ring` provider so Windows builds need no CMake/NASM, rcgen P-256 identity, mdns-sd) with backend traits for display/capture, encoders, input, microphone and power; human-like click timing and the 2 s keyframe rule live in the server so every platform gets them. A software H.264 encoder (OpenH264 compiled from source, BSD-2) is an optional feature, on by default in the CLI, the fallback after hardware encoders; its patent note is in THIRD_PARTY_NOTICES. `sidecast-host` is the CLI with a `--test-pattern` mode like the Mac's; `sidecast-probe` is the Rust conformance client. `scripts/conformance.sh` runs Rust ↔ Rust, Swift probe ↔ Rust host and Rust probe ↔ Mac host, in CI on Ubuntu, Windows and macOS. Dependencies must be permissive (no GPL/LGPL/AGPL). Rust is optional for Mac and Android contributors (`make doctor` only warns). |
| Q37 | **Windows host** (P2, experimental, 2026-10-31): `sidecast-host` (console) and `sidecast-tray` (notification-area app, a GUI-subsystem binary) in `rust/sidecast-host`, on the shared server; Windows 10/11, per-monitor DPI aware so every coordinate is in physical pixels. **Display**: Sidecast ships no display driver (Windows only loads Microsoft-signed drivers, and users are never asked to enable test signing); users install the signed, MIT-licensed Virtual Display Driver (VirtualDrivers/Virtual-Display-Driver) from its official release. While a phone streams, one of its monitors is attached at the phone's pixel size and refresh rate (where the user last had it, else to the right of the desktop) through the documented display-settings API (no administrator rights), and detached afterwards, so no empty screen stays where windows and the pointer get lost; when it is the only display (a headless PC) its previous mode comes back instead. A resolution the driver does not offer is added to its `vdd_settings.xml` and the driver restarted through its named pipe (`RELOAD_DRIVER`; `SETDISPLAYCOUNT 1` when it has no monitor; the driver treats a count of 0 as 1, hence detaching rather than removing); if the file is not writable, the closest offered mode is used and scaled. Without the driver (or when it fails, or the user picks a monitor in the tray), an existing monitor is streamed: the chosen one, else a secondary one, else the primary (mirroring), letterboxed to the phone's shape, and touches map through the same letterbox. Windows picks the virtual monitor's scale (a HiDPI stream has 2× pixels; the user sets 200 % once, remembered per monitor). **Capture**: DXGI Desktop Duplication rather than Windows.Graphics.Capture (no WinRT, no yellow border on Windows 10, explicit desktop and pointer change reports, works on IddCx monitors), re-created after `ACCESS_LOST` (mode changes, full-screen apps, the secure desktop). At most one frame per frame interval and only after a change; each change is copied on the GPU and read back and converted (BGRA → NV12 BT.709 limited, up to 4 threads, pointer drawn in since duplication leaves it out) only once flow control grants a slot, so the last picture still goes out when the phone catches up. **Encoding**: Media Foundation H.264: the GPU's MFT, then Microsoft's software MFT (its H.264 licence comes with Windows), then OpenH264; low latency, CBR changed live, no B-frames, Main profile, a keyframe at least every 2 s plus forced ones (ICodecAPI), BT.709 limited range; output normalized to 4-byte start codes with SPS/PPS (from the media type's sequence header when missing) on every IDR. A new encoder must first encode a test IDR, so a misbehaving driver MFT falls back to the next encoder; a late output is returned by the next call, never dropped. HEVC later. **Input**: SendInput with absolute virtual-desktop coordinates; wheel/hwheel at 2 units per point with remainders (Windows has no scroll phases), pinch = Ctrl+wheel in whole notches, keys with scan codes and the extended flag for the navigation cluster, text as `KEYEVENTF_UNICODE` in grapheme-safe batches. DesktopNext/Previous = Win+Ctrl+→/←, Overview = Win+Tab, AppWindows = Win+D (show the desktop: what a Windows precision touchpad does on a three-finger swipe down; Windows has no App Exposé). Elevated windows and the secure desktop refuse injected input (UIPI), which is logged. **Keep awake**: `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)` from a thread owned by the guard, since the request belongs to a thread. **Microphone**: only with a virtual audio cable the user installed (VB-CABLE): the phone's audio is played into "CABLE Input" with shared-mode WASAPI (48 kHz mono float, converted by Windows), and MIC_CONTROL follows whether an app records "CABLE Output" (its audio sessions, checked twice a second); no cable, no microphone offered. **UI**: Win32 directly (no tray crate): icon, menu, a notification and a large always-on-top window for the pairing code, Start at login through `HKCU\…\Run`, the monitor choice in `settings.json` (`monitor`), logs in `%LOCALAPPDATA%\Sidecast`. **Install**: `scripts/install-windows.ps1` per user into `%LOCALAPPDATA%\Programs\Sidecast` with a Start-menu shortcut, optional autostart, and the firewall prompt explained (allow Private networks). **Tests**: the pure parts (key, shortcut, coordinate and wheel mapping, NV12 conversion and pointer drawing, encoder output, the driver's settings file, cable names) run on every OS; CI on Windows also runs SendInput (pointer position checked), keep-awake, Microsoft's H.264 MFT, real Desktop Duplication of the runner's display streamed to the probe, the tray app, the installer, and the host on a Virtual Display Driver monitor. Not yet tried on a real PC with a phone. |
| Q38 | **Linux host, GNOME on Wayland first** (P3, experimental, 2026-10-31): `sidecast-host` on Linux. **Display**: Mutter's D-Bus `org.gnome.Mutter.ScreenCast` `RecordVirtual` creates a real extra monitor at the phone's pixel size (the size negotiated on the PipeWire stream), cursor as metadata; no consent dialog (the user's own session API, as gnome-remote-desktop uses it; GNOME shows its sharing indicator). Frames come over PipeWire as SHM/MemFd 32-bit RGB (no DMA-BUF modifiers offered) and are converted to I420 BT.709 video range on the capture thread only when flow control has a slot; the latest picture is kept so a dropped one is re-sent when there is room, and a static screen is repeated every 250 ms so the 2 s keyframe rule holds. The pointer is composited from the cursor metadata (Mutter sends its image only when it changes, so a plain arrow stands in until then). For a HiDPI plan the new monitor is set to 200 % through `org.gnome.Mutter.DisplayConfig` `ApplyMonitorsConfig` with the *temporary* method (no confirmation dialog, nothing saved, every other monitor keeps its mode, scale and place), so the desktop on the phone has the plan's size in points like the Mac's 2× display; Mutter alone would pick 100 % for a monitor without a physical size. **Elsewhere on Wayland** (KDE Plasma 6, wlroots): the xdg-desktop-portal's combined RemoteDesktop + ScreenCast session (`ashpd`), a *virtual* source where offered, else a monitor (mirroring), with the portal's dialog once per run. **X11**: refused with a message (no virtual monitor API). `SIDECAST_LINUX_BACKEND=mutter\|portal` overrides the choice. **Input**: the RemoteDesktop session linked to the screencast: absolute motion relative to the stream, evdev buttons and keycodes (layout independent), finger scrolling ending with "finish" so apps do their own kinetic scrolling (the engine's synthetic momentum is not replayed), Ctrl+wheel zoom; swipes → Super+Page Down/Up (desktops), a Super tap (Activities), Alt+Above_Tab (next window of the app; GNOME has no App Exposé). TEXT: ASCII as keysyms; Mutter drops keysyms the active layout lacks, so other characters go through Ctrl+Shift+U (IBus/GTK Unicode entry, everywhere on Ubuntu GNOME) unless `SIDECAST_TEXT_INPUT=keysyms`. CURSOR uses the compositor's pointer from the metadata. **Encoding**: hardware H.264 through GStreamer (`nvh264enc`, `vah264enc`, `vah264lpenc`, `vaapih264enc`, the first that encodes a test frame) behind the `gstreamer` cargo feature, which `make install-linux` enables when the headers are installed; OpenH264 stays the fallback. GStreamer/GLib are LGPL system libraries, linked dynamically and only with that feature (an exception to Q36's crate rule, which still holds: every crate is permissive); no GPL element (x264) is used. **Keep awake**: a logind `sleep:idle` block inhibitor plus GNOME's suspend inhibitor while streaming; the screen lock and lid-close suspend are untouched. **Microphone**: a PipeWire `Audio/Source` "Sidecast Microphone" exists while a mic-capable phone streams; the node runs only while an app records from it, so its Streaming state drives MIC_CONTROL (like the Mac driver's "running somewhere"); it is not made the default input. **UI**: a StatusNotifierItem tray icon with a dbusmenu (status, pairing code, Forget per device, Quit) and the pairing code as a desktop notification, implemented on zbus (no tray crate: the usual one is Unlicense-only); the console log stays, `--no-tray` turns the tray off. **Install**: `make install-linux` → `~/.local/bin`, an app-grid `.desktop`, optional autostart. **Verification**: `scripts/linux-e2e.sh` (`make e2e-linux`, CI job "Linux host on headless GNOME") runs Mutter headless + PipeWire + WirePlumber on a private D-Bus and checks the real backend with `sidecast-probe` (pairing through the notification, decoded frames of the virtual monitor with the pointer, the 200 % scale, input arriving in Mutter and in a Wayland client, CURSOR, the microphone carrying the phone's tone, the tray menu and Quit); it passes with Mutter 46 (Ubuntu 24.04) and 50 (Ubuntu 26.04). Nothing has run on a real desktop with a real phone or GPU yet. |

## Known limitations (accepted for v1)

- `CGVirtualDisplay` is private API; a macOS update can break it.
- Builds are signed with a per-Mac self-signed certificate (Q26, Q33), not a Developer ID: fine for apps built on the same Mac, but a build copied to another Mac would be blocked by Gatekeeper.
- Pairing: an *active* man-in-the-middle present during the 2-minute pairing window could brute-force the 6-digit code. Acceptable on a home network; a PAKE (e.g. SPAKE2) is the upgrade path.
- Dragging the app to the Trash does not remove the sudoers rule — use the menu item "Remove sleep permission…" first.
- One phone at a time (an *authenticated* new phone takes over; unauthenticated connections never disturb the stream).
- Landscape only; no audio from the Mac to the phone; no stylus pressure; no keyboard shortcuts with letters (Cmd+C etc.) from the phone.
